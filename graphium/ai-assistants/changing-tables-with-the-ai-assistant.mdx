## Overview

The AI Assistant can change the structure of your vault's tables for you. In a conversation, you can ask it to add or edit columns on an existing table, create a new table (with rows, if you give it some), or build a table from a spreadsheet you attach. Before it changes anything, the assistant describes what it's about to do and waits for you to agree.

This is turned off in every vault until a vault Admin switches it on.

## When to Use This

- Adding a field your team has started tracking — for example, a **Notes** column on a Medications table
- Renaming a column or adding options to a dropdown column
- Setting up a new table by describing it in plain language instead of building it by hand
- Turning a spreadsheet into a table, or adding a spreadsheet's rows to a table you already have

## Prerequisites

Three settings work together. All of them must be in place for the assistant to make a given change:

1. **Vault settings (vault Admin only).** In the vault, go to **Settings → General**. Under **Assistant table and column changes**, turn on **Let assistants add and edit columns**, **Let assistants create new tables**, or both. See [Vault Settings](/graphium/vaults/vault-settings-general-configuration).
2. **Column access for the table (Admin or Builder).** To add or edit columns on an existing table, that table must be set to **Read & Write** with **Allow column changes** turned on:
   - For the General Assistant, click the ⚙ icon in the chat input bar and use the **Tables** tab — see [Configuring Chat Context and Query Tools](/graphium/ai-assistants/configuring-chat-context-and-query-tools).
   - For a custom assistant, use its **Tools** tab — see [Managing Your AI Assistants](/graphium/ai-assistants/managing-your-ai-assistants).
3. **Your vault role.** You must be a vault **Admin** or **Builder**. Contributors and Viewers don't see the **Allow column changes** switch.

Creating a new table only needs the **Let assistants create new tables** vault setting — there's no per-table switch, because the table doesn't exist yet.

## Step-by-Step Instructions

### Step 1: Ask for the change

On the vault Home page, describe the change in the chat input bar. Name the table and be specific about each column — for example:

- *"Add a text column called Notes to the Medications table."*
- *"Create a Medications table with name, dose, route, and a status of Active, Discontinued or On hold."*
- *"Create a Medications table with name, dose and route, and add these rows: Ibuprofen, 400mg, Oral; Lisinopril, 10mg, Oral."*

### Step 2: Review what the assistant proposes

The assistant doesn't make the change right away. It sets out exactly what it will do — the table name, each column and its type, the options for any dropdown column, and any rows it will add — and asks whether it looks correct.

Read it carefully. If anything is wrong, say what to change (for example, *"Make Dose a number instead"*) and the assistant will set out a revised version.

> 💡 **Tip:** One confirmation covers everything the assistant listed. If you then ask for something that wasn't on the list, it asks again before making that change.

<Frame>
  <img src="/images/graphium/assistant/table-changes-proposal.png" alt="Assistant reply proposing a new table, listing its columns, column types, and rows, and asking whether it looks correct" />
</Frame>

### Step 3: Confirm the change

Reply **yes**. The assistant makes the change and tells you what it did — for example, *"I've created the Medications table with 4 columns and added the 2 rows you specified."*

### Step 4: Check the table

Open the table from the **TABLES** section of the vault sidebar. New columns appear in both the **Data** and **Schema** tabs. Existing records show new columns as empty, ready to fill in.

## What the Assistant Can and Can't Change

The assistant's changes only add to a table — it never removes or reinterprets data that's already there.

| The assistant can | The assistant can't |
|---|---|
| Add columns of these types: Text, Number, Date, Time, Date/Time, Boolean (yes/no), Select from List, Image, and Signature | Delete a column |
| Rename a column or change its description | Change a column's type |
| Add options to a Select from List column | Make a column required — every column it creates is optional |
| Make a required column optional | Add Reference, Formula, or Auto ID columns |
| Create a new table with columns, and add rows to it | Delete or rename a table |

> **Note:** The assistant can create **Image** and **Signature** columns, but it can't fill them in. Those are for people to complete by hand.

## Creating a Table

When you ask the assistant to create a table:

- **Creating a table can't be undone.** There's no way to delete a table afterward, so check the proposal before you reply **yes**.
- **Table names must be unique in the vault.** If a table with that name already exists, the assistant tells you and asks whether to use the existing table or choose a different name.
- **The new table is ready to use in the same conversation.** You can ask the assistant to add or look up records in it right away. This access applies to that conversation only — the table isn't added to the assistant's Chat Context or Tools settings.
- **Changing the new table's columns needs column access.** To add or edit columns on a table the assistant just created, set it to **Read & Write** and turn on **Allow column changes** first, as described in [Prerequisites](#prerequisites).
- **One conversation can create up to 5 tables.** To create more, start a new chat.

## Building a Table from a Spreadsheet

You can attach a spreadsheet and have the assistant build a table from it.

1. In the chat input bar, click the paperclip icon and attach the file. It appears above your message with its row count.
2. Ask for the table — for example, *"Build a table called Providers Import from this file and load all of its rows."*
3. The assistant reads the file and proposes a table: a suggested name, one column per spreadsheet column with a type based on the data, and every row it will load. Columns with a small set of repeating values (such as a Specialty column) become Select from List columns; columns of TRUE/FALSE values become Boolean columns.
4. Reply **yes**. The assistant creates the table and loads the rows in one step, then tells you how many rows it loaded.

A few things to know:

- **Rows with a bad value are skipped, not lost silently.** If a value doesn't fit its column — for example, a word in a number column — the assistant skips that row, tells you which row and why, and loads the rest.
- **Column headers are checked.** If two headers would end up with the same name, or a column has no header, the assistant points it out and asks you to rename it before creating the table.
- **You can load a spreadsheet into a table you already have.** Attach the file and ask, for example, *"Load the rows from this file into Providers Import."* The rows are added to the table — existing records aren't changed or matched up.

## Table Changes in Playbooks

Playbook steps can make the same changes — for example, a step that creates a table from a file that triggered the run. In a playbook, nobody is there to reply **yes**, so a table or column change always pauses the run for approval, even if the table is otherwise set to run without review. The approval card lists each change and what it means for existing records. See [Approving Column Changes](/graphium/playbooks/using-review-checkpoints#approving-column-changes).

To let a playbook change a table's columns, set the table to **Read/Write** and turn on **Allow column changes** in the playbook's access settings. To let it create tables, the vault's **Let assistants create new tables** setting must be on.

## What to Expect

- Every change is made only after you confirm it in chat, or after it's approved in a playbook run.
- New columns show up right away in the table's **Data** and **Schema** tabs.
- If the vault settings are turned off later, any **Allow column changes** switches you turned on for individual tables are kept, and take effect again when the vault setting is turned back on.

## Common Issues & Troubleshooting

| Issue | Likely Cause | Solution |
|-------|-------------|----------|
| An **Access required** card says *Add or edit columns* | The vault setting is off, or the table doesn't allow column changes | Ask a vault Admin to turn on the setting in **Settings → General**, then turn on **Allow column changes** for the table |
| The assistant says it can't add columns, with no card | Column changes aren't allowed for that table in this conversation | Click the ⚙ icon, set the table to **Read & Write**, turn on **Allow column changes**, and ask again |
| The **Allow column changes** switch is missing | The table is set to **Off** or **Read**, or you're a Contributor or Viewer | Set the table to **Read & Write**. If the switch still doesn't appear, ask a vault Admin or Builder |
| The **Allow column changes** switch is greyed out | **Let assistants add and edit columns** is off for the vault | Ask a vault Admin to turn it on in **Settings → General** |
| The assistant won't create a table | **Let assistants create new tables** is off, the name is already taken, or this conversation has already created 5 tables | Ask an Admin to turn on the setting, choose a different name, or start a new chat |
| Some spreadsheet rows didn't load | Those rows had values that didn't fit their columns | Check the rows the assistant named, correct them, and ask it to load them again |
| The assistant won't delete a column or make one required | These changes aren't available to the assistant | Make the change yourself from the table's **Schema** tab |
