## Overview

After a playbook is published, you can edit it — which automatically creates a new version — and disable it when it no longer needs to run. This article covers both.

---

## Editing a Published Playbook

To edit an active playbook, open the playbook from the list and click **Edit** in the top-right header. This immediately creates a new draft version from the currently published version (for example, promoting *v4 · Published* to a new *v5 · Draft*) — a toast confirms *"Draft created from published version."*

Make your changes, then click **Save** to keep them as a draft, or **Publish** to make the new version active immediately. Changes do not affect the currently active published version until you publish again.

<Frame>
  <img src="/images/graphium/playbooks/test-run-buttons.png" alt="Edit button in the playbook editor header, and the new draft version badge after clicking it" />
</Frame>

> **Note:** Each version is numbered sequentially (v1, v2, v3...) and reflects how many times the playbook has been saved or published, whether or not the content actually changed. There is currently no dedicated version-history browser for reviewing or reverting to a specific older version — to undo unwanted changes, edit the playbook back to the desired configuration and publish again.

## Disabling a Playbook

To stop a playbook from running, toggle it off from the Playbooks list: find the **Enabled / Disabled** toggle in the bottom-right corner of the playbook's card and click it. No confirmation is required — the card updates immediately to show **Disabled**.

A disabled playbook will not fire on schedule, cannot be triggered manually, and will not respond to connection or vault events until re-enabled. For connection-triggered playbooks, disabling also pauses the deployed trigger on the external service.

## Troubleshooting

| Issue | Likely Cause | What to Do |
|-------|--------------|------------|
| Clicking Edit changed the version number even though nothing was edited yet | This is expected — Edit always forks a new draft version from the currently published one | If you don't want to keep the new draft, simply leave it unpublished; the previously published version remains active for other users |
| Can't find a way to view or restore an older version | There is no dedicated version-history browser currently | Re-create the desired configuration by editing the playbook and publishing again |
| Disabled playbook still shows a recent run | The run may have started just before you disabled it | This is expected — disabling only prevents new runs from starting, it does not stop a run already in progress |
