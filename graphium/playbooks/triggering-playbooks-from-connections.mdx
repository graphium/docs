## Overview

Beyond **Manual** and **Scheduled** triggers, playbooks can run automatically in response to activity in your vault or in a connected external system. A **Vault Event** trigger fires when a record is added, updated, or deleted in a specific table. A **Connection Event** trigger fires when something happens in a connected system — a new row in a spreadsheet, a new file over SFTP, a new deal in HubSpot, and so on.

All triggers are configured from the same place: click the **trigger card** at the top of the playbook's flow canvas to open **Trigger Configuration** in the right panel, then use the **Run when** dropdown to search and select a trigger type. There is no separate trigger picker modal — everything happens inline in this panel.

---

## Choosing a Trigger

Open a playbook in the editor and click the **trigger card** at the top of the flow canvas.

In the **Trigger Configuration** panel, click the **Run when** dropdown and use the search field to find the trigger you want. Options are grouped by category:

- **General** — Manual, Scheduled
- **Vault Events** — Record Added, Record Updated, Record Deleted
- **Connected System** — for example, a vault with HubSpot connected shows a **HubSpot** group listing its available trigger events

Only connections that have actually been added to the vault appear in this list — if you don't see a connection you expected, confirm it has been added under [Connections](/graphium/connections/adding-a-new-automated-connection) first.

## General Event Triggers

General triggers aren't tied to a vault table or a connected system — they're either started by a person or fired on a schedule. Two types are available:

- **Manual** — Fires only when someone clicks **Run** in the playbook editor or dashboard. No additional configuration is required beyond an optional Description.
- **Scheduled** — Fires automatically on a recurring schedule.

After selecting **Scheduled** from the **Run when** dropdown, configure:

- **Frequency** — How often the playbook runs (for example, Daily, Weekly).
- **Time** — The time of day the run should start.
- **Time Zone** — The time zone used to evaluate the scheduled time.
- **Description** (optional) — Document when and why this playbook runs.

## Vault Event Triggers

Vault Event triggers fire when a record in one of your vault's tables changes. Three types are available:

- **Record Added** — Fires when a new record is created in the selected table.
- **Record Updated** — Fires when an existing record in the selected table is modified.
- **Record Deleted** — Fires when a record in the selected table is deleted.

After selecting one of these from the **Run when** dropdown, configure:

- **Select table** — The vault table to watch for the event.
- **Description** (optional) — Document when and why this playbook runs.

## Connection Event Triggers

Connection Event triggers fire when something happens in a connected external system. The available events depend on which connection you select, for example:

| Connection | Example Trigger Events |
|------------|------------------------|
| Google Sheets | New Row Added |
| Graphium EMR | New Case, New Case Update, New Document |
| FTP/SFTP | New File Added (Polling) |
| HubSpot | New Deal in Stage, New Form Submission, New or Updated Company, New or Updated Contact, New or Updated Deal, New Ticket |

<Frame>
  <img src="/images/graphium/playbooks/connection-event-trigger.png" alt="Trigger Configuration panel showing a connection event trigger selected" />
</Frame>

> **Note:** Events marked **(Polling)** are checked on a regular interval rather than delivered instantly — there may be a short delay between the event happening and the playbook running.

## Configuring Connection Trigger Parameters

Once you select a connection event, the panel shows fields specific to that trigger.

**Example: Google Sheets "New Row Added"**

- **Spreadsheet** (required) — The Google Sheets file to watch.
- **Worksheet(s)** (required) — The specific sheet(s) within the spreadsheet to watch for new rows.

**Example: HubSpot "New or Updated Contact"**

- **Additional properties to retrieve** — Extra contact properties to include in the event payload.
- **Lists** — Restrict the trigger to contacts belonging to specific HubSpot lists.
- **New Only** — When enabled, only fires for newly created contacts rather than updates to existing ones.

Every connection trigger also has an optional **Description** field, and a **Clear all** link to reset the current trigger configuration.

## Selecting Playbook Access

The **Playbook Access** panel controls every resource a playbook can use — its **Tables**, **Connections**, and **Tools** — not just its trigger.

1. In the left sidebar, click **Configure shared access** to open the **Playbook Access** panel.
2. Toggle on any tables, connections, or tools this playbook's steps need.
3. Toggling a connection type on reveals an **Actions** row showing how many actions are enabled (for example, *10 of 10 actions*). Click it to expand the full list, where each action has its own checkbox alongside **Select all** and **Clear** links — use this to scope the connection down to only the actions this playbook actually needs.

   > **Note:** A connection must have at least one action enabled, or be turned off entirely. If a connection is toggled on with zero actions selected, the playbook cannot be saved or published until this is fixed — see Troubleshooting below.

## What Happens at Publish

When you publish a playbook with a Vault Event or Connection Event trigger:

- The trigger is registered with the vault or the external service.
- The playbook begins listening for the configured event immediately.
- Graphium AI validates the playbook's configuration, including that every enabled connection has at least one available action — if a problem is found, publishing is blocked and the specific issue is called out so you can fix it before trying again.

## Troubleshooting

| Issue | Likely Cause | What to Do |
|-------|--------------|------------|
| A connection is missing from the Run when dropdown | The connection has not been added to this vault | Add it under [Connections](/graphium/connections/adding-a-new-automated-connection), then return to the playbook editor |
| "This playbook can't be saved yet" / "A connection must keep at least one action, or be turned off" | A connection is toggled on in Playbook Access but has zero actions selected | Open Playbook Access, expand the connection's Actions list, and select at least one action — or turn the connection off |
| Vault Event trigger never fires | The selected table doesn't match where records are actually being added or changed | Confirm the correct table is selected in the trigger's configuration |
| Connection trigger never fires | The connection may be disconnected, or the event is a (Polling) type with a delay | Check the connection's status under Connections, and allow time for polling intervals to elapse |
| Trigger fields are missing after selecting a trigger type | The panel may not have refreshed | Close and reopen the trigger card, or refresh the page |
